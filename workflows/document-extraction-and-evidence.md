# 文件抽取与证据链 Agent 工作流

## 适用用户

造价审核人员、结算/审计人员、合同商务人员、项目经理、需要处理大量项目文件的咨询人员。

## 输入文件

- Excel 清单、台账、结算书、材料价格表。
- PDF/Word 合同、招标文件、会议纪要、签证单。
- 扫描件、图片、邮件和附件。
- DWG/DXF 图纸（按 `references/dwg-cad-handling.md` 的能力边界处理）。
- 项目已有的证据索引、资料清单或往来函件。

## 模式判断

| 任务模式 | 重点 | 主要输出 |
|---|---|---|
| 合同/招标审查 | 条款、付款、调价、风险、签章 | 条款证据索引、资料完整性清单 |
| 结算/审计 | 结算组成、变更、签证、付款、扣回 | 证据索引、问题台账、需补资料 |
| 变更/签证审核 | 事件事实、书面指令、时效、数量、单价、附件 | 变更索赔证据清单 |
| 材料调差 | 基准期、施工期、信息价、询价、合同范围 | 价格证据索引、调差表 |
| 地铁/轨道交通 | 车站/区间清单、地质、盾构、监测、穿越 | 地铁证据索引、专项清单 |
| 投标/清标 | 招标文件、评标办法、投标报价、澄清 | 清标证据索引、澄清问题清单 |

## 执行步骤

1. 建立文件清单：文件名、类型、页数/工作表、版本、日期、签章状态、可读性。
2. 识别文件用途和适用任务，选择对应的 input-spec、workflow 和 template。
3. 抽取字段并记录来源：文件名 + 页码/行号/工作表/条款号；扫描件标注 OCR。
4. 建立证据索引：每条关键事实对应证据编号、可靠性、关联问题和缺失项。
5. 交叉核对：同一金额、日期、数量、签字和条款在不同文件中是否一致；版本是否冲突。
6. 检查资料完整性：按任务列出必备资料、已提供、部分提供和缺失。
7. 输出证据缺口：读不到、读不全、版本冲突、OCR 不确定、无签章、无附件的事项，列入需补资料/人工确认。
8. 按 `workflows/second-pass-review.md` 质检，重点检查证据链、结论强度和资料完整性。

## 中间判断

- 文件是原件、复印件、扫描件还是 OCR 结果；是否签章、是否有附件。
- 同一事实在不同文件中的金额、日期、数量、签字是否一致。
- 会议纪要、邮件、聊天记录是否构成合同指令；不能直接替代书面指令。
- 文件版本是否冲突；报审版、审核版、定案版、盖章版是否分清。
- 扫描件/图片的数字、日期、金额、签字是否可辨认；是否需要原件。
- DWG/DXF 只能做到 L1/L2 还是 L3；不能承诺完整算量。
- 资料缺失是否影响结论强度；缺关键资料时是否降级。

## 输出成果

- `templates/evidence-index.md`
- `templates/need-more-documents-list.md`
- `templates/management-summary.md`
- 对应任务的审核报告/台账/清单
- 质检摘要（按 `templates/second-pass-review-report.md`）

## 风险控制

- 不编造文件内容、页码、条款号、签字人、金额或日期。
- 不把会议纪要当成书面指令，不把复印件当成原件，不把 OCR 当成已核对。
- 不在文件无法读取时假装已核对；读不到就写“无法读取/需原件/需 OCR”。
- 不自动上传项目文件到外部 OCR/在线工具；第三方工具需用户确认。
- 不承诺 DWG 完整算量或替代专业图纸阅读。
- 只提取审核必需字段，避免扩散个人信息和商业秘密。

## 人工确认点

- 文件版本和签章状态。
- OCR/扫描件的关键数字、日期、金额和签字。
- 会议纪要、邮件和聊天记录是否构成合同指令。
- 缺失资料是否影响最终结论。
- 涉及保密、个人信息或第三方工具的使用。
