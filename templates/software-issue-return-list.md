## 三、状态字典

| 字段 | 取值 | 说明 |
|---|---|---|
| 判断等级 | 确定问题 / 疑似问题 / 待补资料 / 人工确认 | 与 `workflows/second-pass-review.md` 一致 |
| 严重程度 | 错误 / 警告 / 提示 | 脚本输出使用；本表可并入“问题类型” |
| 软件回填状态 | 待处理 / 处理中 / 已修改待复检 / 已关闭 / 不修改 | 每条问题都要有最终状态 |
| 复核结论 | 通过 / 需修正 / 不适用 | 复检时填写 |
| 关闭依据 | 新导出文件、行号、截图或平台校验结果 | 不能只写“已处理” |

## 四、使用步骤

1. 先运行 `scripts/check_software_export.py` 生成问题回填 CSV，再按本表整理。
2. 把脚本的“单位工程/工作表、数据行号、清单编码”原样保留，便于在软件中定位。
3. 由造价人员在原软件中修改，不直接编辑导出的 Excel 或招标人提供的 `.24jz` 清单。
4. 修改后重新导出，使用同一命令复检，并在本表填写“已修改待复检/已关闭”。
5. 对“不修改”的问题写明理由和依据，由复核人确认。
6. 投标、清标、结算或对外交付前，按 `workflows/second-pass-review.md` 生成质检摘要。

## 五、注意事项

- 一条问题只对应一个字段或一个处理动作；不要把多个问题合并成一行。
- 金额、编码和行号必须与导出文件一致；不得凭记忆填写。
- 四舍五入差异、单位异常、同名重复项等只能标记为“疑似/人工确认”，不得直接认定为错误或违法。
- 涉及暂列金额、暂估价、增值税税率、安全生产措施费费率和不可竞争费用的修改，必须有招标文件、合同或平台规则依据。
- 本表保留人工复核和签认栏，AI 不得作为签认人。
