# 文件抽取与证据链参考

> 本文件用于从 Excel、PDF、Word、扫描件、图片、邮件、会议纪要和 DWG/DXF 中抽取造价审核所需信息，并建立可追溯的证据索引。
>
> 目标不是“把所有文件读一遍”，而是明确：读到了什么、来自哪一页/行/工作表、可靠性如何、缺什么、哪些必须人工确认。

## 一、能力边界

- 可以做：识别文件类型、提取字段、建立证据索引、检查资料完整性、标注 OCR/版本/签章风险。
- 不能做：替代 OCR 软件、Excel/PDF 解析库、CAD 算量、BIM 或专业图纸阅读；不能在没有原文件时还原内容。
- 扫描件、图片和加密 PDF 可能无法读取或只能 OCR；必须标注不确定性和人工复核。
- DWG/DXF 只能按 `references/dwg-cad-handling.md` 的 L1/L2/L3 能力边界处理，不承诺完整算量。
- 不编造文件内容、页码、条款号、签字人或金额；读不到就写“无法读取/需原件/需 OCR”。

## 二、文件类型与可靠性

| 类型 | 可提取内容 | 可靠性 | 注意事项 |
|---|---|---|---|
| Excel 清单/台账 | 工作表名、单元格、合并单元格、公式结果、行号 | 高（原始电子文件） | 区分公式和值；合并单元格可能导致错位；隐藏行/列要检查 |
| PDF 原生文本 | 文字、表格、页码、书签 | 中高 | 版式和跨页表格可能错位；扫描页需 OCR |
| PDF 扫描件/图片 | OCR 文字、版式线索 | 低到中 | 必须标注 OCR；数字、签字、手写和印章易误读 |
| Word 合同/纪要 | 段落、表格、批注、修订 | 中高 | 区分正文、批注、修订和附件；会议纪要≠书面指令 |
| 邮件/聊天记录 | 时间、发件人、正文、附件名 | 中 | 可作为事实线索，不一定构成合同指令 |
| DWG/DXF | 图层、文字、块、几何（L2） | 中低 | 见 DWG 能力边界；不能自动识别构件或完整算量 |
| 纸质原件照片 | OCR/人工摘录 | 低 | 必须核对原件、签字和盖章 |

## 三、抽取流程

1. 建立文件清单：文件名、类型、大小、页数/工作表、版本、日期、是否签章、是否可读。
2. 识别文件用途：合同、招标文件、清单、图纸、地质资料、变更签证、材料价格、付款、结算、验收、监测等。
3. 抽取字段并记录来源：文件名 + 页码/行号/工作表/单元格/条款号。
4. 建立证据索引：每条事实对应一个证据编号和可靠性等级。
5. 交叉核对：同一事实在不同文件中的金额、日期、数量、签字是否一致。
6. 检查资料完整性：按任务列出必备资料和缺失项。
7. 输出：证据索引、资料完整性清单、抽取摘要、需补资料和人工确认点。

## 四、证据索引字段

| 字段 | 说明 |
|---|---|
| 证据编号 | E-001 起，按任务或文件分组 |
| 文件名 | 原文件名，不改名 |
| 文件类型/版本 | Excel/PDF/Word/扫描件/DWG；版本号或日期 |
| 页码/行号/工作表 | 能定位到原文的最小位置 |
| 关键事实 | 金额、日期、条款、数量、签字、审批等 |
| 关联问题 | 对应审核问题编号或台账行 |
| 可靠性 | 高/中/低；说明原件/复印件/OCR/未签章 |
| 缺失/备注 | 缺页、模糊、无签字、版本冲突、需原件 |

## 五、资料完整性清单

### 合同/招标

- 合同协议书、专用条款、通用条款、补充协议。
- 招标文件、评标办法、答疑澄清、中标通知书。
- 合同清单、已标价工程量清单、综合单价分析表。

### 清单/图纸/地质

- 工程量清单、设计图纸、设计说明、做法表。
- 地勘报告、地下管线资料、周边建构筑物资料。
- 图纸版本、会审记录、设计变更。

### 变更/签证/索赔

- 变更指令、签证单、会议纪要、照片/影像。
- 工程量计算书、单价分析、材料/机械凭证。
- 时效证明、授权签字、监理签认。

### 材料价格/付款/结算

- 信息价期别、询价单、采购合同、发票。
- 进度款申报、付款台账、预付款扣回、质保金台账。
- 结算书、工程量计算书、竣工图、验收资料。

### 地铁/轨道交通专项

- 车站/区间清单、地质资料、盾构掘进记录、管片资料。
- 监测方案/报告、穿越审批、交通导改/管线迁改资料。
- 详见 `references/metro-rail-transit.md`。

## 六、可靠性分级与表述

- 高：原始电子文件、签章原件、可直接定位到页码/行号/工作表。
- 中：复印件、扫描件 OCR、未签章版本、内容基本可读但需复核。
- 低：模糊扫描、手写、图片、会议纪要、无签字/无附件的陈述。
- 证据不足时使用“疑似/待补/需原件/需 OCR/需人工确认”，不要写成确定事实。
- OCR 结果必须标注“OCR 识别，需人工核对”，数字、日期、金额和签字尤其要复核。

## 七、版本与重复文件

- 同一文件可能有报审版、审核版、定案版、盖章版、扫描版；必须记录版本和日期。
- 文件名相同但内容不同，应计算摘要或对比关键字段，不能默认最新文件就是有效版本。
- 合同、变更、签证和结算的版本冲突应列为待确认事项，不自行选择“看起来更合理”的版本。

## 八、安全与保密

- 项目文件可能含商业秘密、个人信息和投标人数据；只提取审核必需字段，不额外扩散。
- 不在输出中暴露无关的个人电话、身份证号、银行账号等敏感信息。
- 第三方 OCR、CAD 脚本或在线工具需用户确认；不自动上传项目文件到外部服务。
- 对外提交前，按项目保密要求做脱敏和权限控制。

## 九、输出要求

- 每个审核意见至少对应一个证据编号；没有证据的结论必须降级。
- 证据索引和资料完整性清单随审核成果一起交付。
- 读不到、读不全、版本冲突和 OCR 不确定，必须写入需补资料/人工确认。
- 不把“文件存在”当成“内容已核实”；不把“会议纪要”当成“书面指令”。
