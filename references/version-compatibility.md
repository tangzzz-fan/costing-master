# 版本兼容与适用范围

> 状态：草案，待人工确认。
>
> 用途：说明 Skill 版本、标准索引版本、地方规则版本和 CI 门槛之间的对应关系，供交付包记录和升级判断使用。

## 一、交付包必须记录的四元组

| 字段 | 取值来源 | 示例 |
|---|---|---|
| Skill 版本 | `SKILL.md` 的 `metadata.version` | 0.13.0 |
| 标准索引版本 | `references/standards-index.md` 状态行 | v0.5 |
| 地方规则版本 | `references/region-jiangsu-shanghai-zhejiang.md` 的 L 编号 | L01 江苏/苏州 |
| CI 状态 | 最近一次质量报告 | 七步通过 |

四元组缺任意一项，交付包只能作为草稿。

## 三、兼容判定

| 场景 | 判定 | 处理 |
|---|---|---|
| 同 Skill 版本 + 同标准索引版本 | 完全兼容 | 可直接复用交付包 |
| 新标准索引 + 旧 Skill 版本 | 条件兼容 | 先复核差异条目，必要时升级 Skill，不得静默沿用 |
| 地方规则新增、废止或执行时间变化 | 不兼容 | 至少按 patch 版本发布，并更新 `standards-index.md` 和受影响测试 |
| 跨地区项目 | 不兼容 | 切换到项目所在地地方规则集，不得跨地区套用费率或指标 |
| 国家标准换版 | 不兼容 | 按合同日期划断，旧项目保留旧版判定，见 `scripts/test_project_applicability.py` |

## 四、升级步骤

1. 更新 `references/standards-index.md` 和 `references/region-jiangsu-shanghai-zhejiang.md`，记录核对日期。
2. 更新受影响测试用例和 `rules/rule-registry.json`。
3. 运行 CI 七步，确认 `validate.py`、`check_rule_governance.py`、`eval_workflows.py` 通过。
4. 在 `CHANGELOG.md` 记录变化范围、影响项目类型和已知限制。
5. 更新交付包的四元组和复核日期。

## 五、回滚

- 每个发布版本保留对应的标准索引快照和测试状态。
- 回滚时同时回退 Skill 版本、标准索引和测试数据，不得只回退其中一项。
- 回滚后重跑 CI 七步，并在交付包中记录回滚原因和日期。
