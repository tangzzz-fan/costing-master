# 企业级交付与审核记录参考

> 目标：把造价审核成果从“能生成”提升为“可复核、可追溯、可归档、可交付”。
>
> AI Agent 只能生成工作底稿、证据索引、计算和质检建议，不能替代注册造价工程师签章、企业审批、评标委员会判断或法律意见。

## 一、角色与职责

| 角色 | 主要职责 | 可签认内容 | 边界 |
|---|---|---|---|
| 编制人/造价员 | 整理资料、计算、编制报告和台账 | 工作底稿编制记录 | 不能自审自签 |
| 复核人/审核人 | 独立复核证据、计算、口径和结论 | 复核记录、审核意见 | 不得与编制人同一人 |
| 成本负责人/商务负责人 | 复核商业影响、成本口径和处置方案 | 成本/商务审核意见 | 不替代专业签章 |
| 项目负责人/企业授权人 | 决定是否对外交付、是否盖章 | 对外交付批准、签章 | 必须有企业授权 |
| 法务/合规 | 合同解释、法律风险、保密审查 | 法务/合规意见 | 不出具造价结论 |
| AI Agent | 抽取文件、整理证据、计算、生成初稿和质检建议 | 不签认、不盖章、不代替注册造价工程师 | 只输出工作底稿和待人工确认事项 |

## 二、交付物清单

| 交付物 | 内容 | 是否必备 | 备注 |
|---|---|---|---|
| 封面和目录 | 项目、任务、版本、日期、编制/审核角色 | 是 | 标明“工作底稿/送审稿/定案稿” |
| 任务说明 | 用户原始任务、范围、输出要求 | 是 | 防止漏项 |
| 数据来源和版本 | 合同、清单、图纸、信息价、标准/地方文件版本 | 是 | 引用证据索引 |
| 主要假设和限制 | 缺资料、估算假设、口径边界 | 是 | 不得隐藏关键假设 |
| 主报告 | 审核报告/预算/结算/成本分析 | 是 | 结论强度与证据匹配 |
| 台账/计算表 | 审减审增、变更、调差、成本偏差等 | 视任务 | 合计闭合 |
| 证据索引 | 文件、页码/行号/工作表、关键事实、可靠性 | 是 | 使用 `templates/evidence-index.md` |
| 需补资料清单 | 缺失资料、待确认事项 | 是 | 使用 `templates/need-more-documents-list.md` |
| 质检摘要 | 二次审核结果、问题、修正 | 是 | 使用 `templates/second-pass-review-report.md` |
| 审核记录 | 复核人、意见、处理结果、签认 | 是 | 使用 `templates/review-record.md` |
| 修订记录 | 版本、日期、修改内容、修改人 | 是 | 不得覆盖旧版本 |
| 文件清单 | 交付包内所有文件、版本和状态 | 是 | 使用 `templates/delivery-package.md` |
| 保密说明 | 数据敏感级别、脱敏和访问限制 | 视项目 | 对外交付前必须检查 |

## 三、审核 gate

| Gate | 审核内容 | 审核人 | 通过标准 |
|---|---|---|---|
| G1 资料完整性 | 合同、清单、图纸、地勘、信息价、付款等 | 编制人+复核人 | 缺失项已列入需补资料 |
| G2 证据和计算 | 证据链、金额闭合、台账合计 | 复核人 | 关键结论有证据编号；计算闭合 |
| G3 标准和地方适用 | 标准版本、地方执行时间、合同划断 | 复核人/造价专业人员 | 标准索引和场景版本一致 |
| G4 结论和风险 | 结论强度、商务/法律边界、重大风险 | 成本负责人/法务 | 不把疑似写成确定，不越界法律结论 |
| G5 交付包和兼容 | 交付物齐全、版本一致、CI 通过 | 项目负责人 | 文件清单完整，版本可追溯 |
| G6 签认和对外交付 | 审核记录、授权、签章 | 企业授权人 | 人工签认后才能对外 |

## 四、审计轨迹

- 每个关键事实对应证据编号（E-001 起），记录文件名、页码/行号/工作表、可靠性和关联问题。
- 每个交付文件有版本号、日期和状态：工作底稿、送审稿、审核稿、定案稿。
- 审核意见必须记录提出人、处理人、处理结果和关闭日期。
- 修改不得覆盖旧版本；保留修订记录和关键差异。
- 记录适用标准、地方规则、信息价期别、Skill 版本和 CI 状态。
- 对外交付前检查文件清单、签认页、保密说明和附件完整性。

## 五、文件命名与版本

建议格式：

```text
项目简称_交付物_版本_状态_日期
例：苏州地铁VIII-TS-08_结算审核报告_v1.0_审核稿_20261018
```

- 不使用“最终版”“最新版”“修改版”等无法追溯的名称。
- 草稿、审核稿、定案稿必须区分。
- 同一文件的不同版本并存，不覆盖。
- 交付包内的文件清单必须与磁盘文件一致。

## 六、版本兼容

- 交付包记录 Skill 版本、标准索引版本、地方规则版本和测试状态。
- 标准或地方规则更新后，旧交付包不应静默沿用；应标注适用版本和复核日期。
- CI 七步（结构校验、规则治理、业务断言、标准变动断言、地区适用性断言、工程量公式断言、评估报告）通过是内部交付的最低技术条件，不替代专业审核。
- 版本不兼容时，先更新索引、测试和报告，再交付。

## 七、保密与归档

- 项目文件可能含商业秘密、个人信息、投标人数据和合同敏感条款。
- 只提取审核必需字段，对外交付前脱敏。
- 访问权限按角色分配；离职/项目结束后回收。
- 归档保存期限按企业制度和合同约定执行；至少保留报告、证据索引、审核记录和修订记录。
- 不把含敏感信息的项目文件提交到公开仓库或外部服务。

## 八、团队模板

- 角色分配表：编制人、复核人、成本负责人、项目负责人、法务/合规。
- 审核记录：`templates/review-record.md`
- 交付包清单：`templates/delivery-package.md`
- 证据索引：`templates/evidence-index.md`
- 质检摘要：`templates/second-pass-review-report.md`
- 工作流：`workflows/enterprise-delivery.md`

## 九、边界

- AI 不是注册造价工程师，不签章、不盖章、不出具法律意见。
- 企业审批、评标委员会判断、审计机关结论和合同解释由相应授权人员负责。
- 交付包完整不等于结论正确；证据、计算和专业判断仍需人工复核。
- 对外交付必须有人工签认和授权；未签认的输出只能作为工作底稿。
